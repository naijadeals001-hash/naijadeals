PERSISTENCE LOGIC DETAILS

CONCURRENCY: Pessimistic row-level locking implemented on Ledger and Settlement tables to prevent double-spending during high-load settlement cycles.
ISOLATION: Repeatable Read isolation level ensures that within a transaction, the state of the Escrow and its Milestones remains consistent across multiple reads.
DATA TYPES: All IDs are UUID v7 (time-ordered) for optimal indexing. Financial values utilize the DECIMAL(20, 8) format.

INDEXING STRATEGY

  • idx_escrow_buyer_id (btree) - Optimized for user dashboard queries.
  • idx_settlement_status (hash) - Fast lookup for pending transfers.
  • idx_audit_log_timestamp (brin) - Efficient range scans for huge historical datasets.
  • idx_ledger_tx_hash (unique) - Integrity constraint for distributed settlement records.
