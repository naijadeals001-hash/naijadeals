# WF-008: Deep Technical Integration Guide

## 1. Microservice Orchestration

`Notification_Core` operates as a downstream consumer of `Workflow_Engine`. All events emitted from the engine are serialized into JSON and pushed to a RabbitMQ exchange. This service pulls from the `pending_notifications` queue and resolves channel mapping based on user preferences.

## 3. Latency Mitigation

To maintain < 12ms latency, the service uses an in-memory Redis cache for frequently accessed user preferences. Cache invalidation occurs via TTL (300s) or explicit `preference_update` events.
